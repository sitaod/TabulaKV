成果简介

本项目围绕基于 KV Cache 压缩的表格问答结构化推理优化展开研究与实现。项目搭建了支持 KV Cache 压缩算法管理的框架，并围绕表格问答任务搭建了评测、日志和结果分析流程，并探索了针对表格问答场景的 KV Cache 压缩算法。

项目主要完成了以下几方面的工作。

第一，搭建了支持 KV Cache 压缩算法管理的推理框架。在 Artifact-Infer 推理框架的基础上，项目完善了 Cache Manager、压缩器注册机制和统一的压缩调用接口，使不同 KV Cache 压缩算法能够在同一套推理流程中运行。框架支持从配置文件指定压缩方法、缓存预算、chunk size、question window 等参数，避免将实验逻辑写死在模型推理代码中。通过这种方式，后续新增算法时只需要实现对应的压缩器逻辑，即可复用已有的模型加载、prefill、decode、KV Cache 读写和日志记录流程。

第二，搭建了 WikiTableQuestions 表格问答评测流程。项目将表格统一表示为 list-of-lists 格式，并构造统一的 prompt 模板，使 Full KV Cache 与不同压缩方法在相同输入形式下进行比较。评测流程支持通过配置文件控制模型路径、数据文件、评测数量、生成参数和压缩策略，并能够记录逐条样本的问题、模型输出、标准答案和正确性结果。这样既方便统计整体表现，也方便回看具体失败样本，分析压缩后模型是否丢失了关键表格信息。

第三，实现并适配了多种 KV Cache 压缩方法作为对照，包括 RKV、SnapKV、Sliding Window、Question-aware 压缩等。项目对这些方法进行了统一封装，使其能够共享相同的缓存管理接口和实验配置。在 KV Cache 压缩算法的实现与实验设计的过程中，为了保证比较尽量公平，项目将 few-shot 示例部分设计为 protected prefix，使示例 KV Cache 直接保留而不占用当前样本的压缩预算；当前样本的真实表格、问题和回答引导部分则在统一预算下进行压缩。这样可以减少 few-shot 示例挤占 budget 对实验结果的干扰，使不同压缩策略的差异更多来自其对当前表格内容的选择能力。

第四，围绕表格结构特点提出并实现了 TabulaKV 压缩算法，用于探索将表头、列属性和问题相关性引入 KV Cache 选择过程。该方法基于 question-aware 的 KV 选择思想，引入表格结构信息，对真实表格中的表头单元格和表体单元格建立 token-level 的元数据。压缩时，方法使用问题 token 对候选 KV 进行 cross-attention 打分，并利用表头与正文单元格之间的列关系对分数进行调整。该算法对表头信息施加保护，每表头单元格至少保留一个注意力分数较高的 token；表体单元格的分数受到对应列表头分数的加权影响。 TabulaKV 在评测结果上与其他已有的 KV Cache 压缩算法相近，但它在部分依赖列语义定位的案例中展现出一定潜力，为后续结构化 KV Cache 压缩提供了可继续扩展的原型。

项目研究创新点与学术价值

本项目的创新点与学术价值主要体现在以下几个方面。

第一，项目将 KV Cache 压缩问题放在结构化表格问答场景中进行研究，而不仅仅关注通用长文本压缩。表格数据具有明显的二维结构，包括表头、行、列、单元格以及问题所指向的属性关系。传统 KV Cache 压缩方法多以 token 注意力、相似度或位置邻近性为核心，较少显式考虑表格内部的结构关系。本项目尝试将表格的 header-cell、body-cell 和 column 关系转化为 token-level metadata，并将其引入 KV 选择过程。这一设计的意义在于，表格任务中的缓存压缩不再只是选择注意力分数最高的若干 token，而是开始考虑这些 token 在结构化数据中的语义角色，为表格场景下的 KV Cache 压缩提供了新的研究思路。

第二，项目在 Artifact-Infer 基础上加入了 KV Cache 压缩算法管理功能。通过统一的 Cache Manager 和压缩器接口，不同算法可以复用同一套模型加载、推理调度、缓存读写和日志记录流程。这种设计降低了新增压缩方法的工程成本，也便于后续进行系统性对照实验。

第三，项目提出并实现了 question-aware 与 table-aware 结合的 TabulaKV 方法。该方法以问题 token 对 prompt token 的 cross-attention 作为基础相关性信号，同时进一步引入表格结构信息，对真实表格中的表头单元格和表体单元格建立 token-level metadata。与只依据全局 top-k 注意力或最近 token 的压缩方法不同，TabulaKV 将表头视为表格列语义的重要载体，并设计了表头单元格的最低保留约束，使每个表头 cell 至少保留一个高相关 token，避免压缩后完全丢失某一列的属性名称。对于表体单元格，TabulaKV 进一步利用其所属列的表头注意力得分修正自身得分，即当某个单元格处在表格正文中时，其保留分数不仅由自身与问题的相关性决定，也受到对应列表头与问题相关性的影响。这种设计通过可调的 lambda 参数在 token 自身相关性和列属性相关性之间进行平衡，使模型在压缩 KV Cache 时能够更偏向保留问题所关注列中的信息。
TabulaKV 的学术价值在于尝试将结构归纳偏置引入 KV Cache 压缩过程。表格问答通常需要模型先理解问题涉及的属性，再根据表头和单元格之间的列关系定位答案。若压缩过程只保留孤立 token，即使这些 token 本身注意力较高，也可能破坏表格中的属性对应关系。TabulaKV 通过表头保留、列关系传播和问题相关性加权，探索了一种将二维表格结构映射到一维 KV Cache 选择过程的方法。虽然当前实验中 TabulaKV 尚未在总体准确率上形成稳定优势，但它在部分依赖列语义定位的样本中表现出一定潜力，也揭示了后续研究需要进一步处理行级关系、cell 级整体保留和结构化 budget 分配等问题。

第四，项目形成了一套可复用的实验基础设施。评测脚本、配置文件、日志体系、压缩器注册机制和使用文档已经基本成型。后续研究者可以在此基础上快速新增压缩策略，调整 budget、chunk size、question window、lambda 等参数，并在相同评测流程中进行对照。这部分工程建设不仅服务于本项目实验，也为继续研究表格问答、长上下文推理和结构化 KV Cache 压缩提供了可复用基础。

总体来看，本项目验证了一个重要问题：在表格问答任务中，简单依赖 token-level 压缩并不总能保留完成推理所需的结构关系。即使 question-aware 方法能够提高部分相关 token 的保留概率，也可能因为缺少行级、列级或单元格级整体约束而丢失答案定位所需的结构上下文。因此，表格任务中的 KV Cache 压缩不仅是“保留哪些 token”的问题，也是“如何在有限缓存预算下保留结构关系”的问题。这一观察为后续研究提供了明确方向。

项目执行过程与实施情况

项目执行大致分为七个阶段。

一、项目调研。在项目建立之初，项目成员以面向表格问答结构化推理的强化学习后训练技术优化研究为主题展开文献调研，关注了加速解码技术、后训练微调与强化学习技术、KV Cache 压缩技术、思维链与思维树范式等方面内容，并调研了表格相关的数据集和工作，如 Table Bench，Table-R1等。最终确定了 KV Cache 压缩的研究方向。

二、框架整理与功能扩展。项目以 Artifact-Infer 为基础，梳理现有推理流程和缓存管理逻辑，在框架中增加 KV Cache 压缩算法管理能力，使不同压缩算法能够通过统一接口接入。

三、评测任务建设。项目为 WikiTableQuestions 数据集构建了评测程序，将表格统一组织为 list-of-lists 格式，并构造固定 prompt 进行测试。评测程序支持从配置文件读取模型路径、数据路径、评测条数、生成参数和压缩策略，避免在代码中硬编码实验设置。日志部分记录每条样本是否正确，并保存问题、模型输出和标准答案，便于后续分析。

四、基线与已有压缩方法适配。项目完成 Full KV Cache 基线测试，并适配了 RKV、SnapKV、Sliding Window 等方法。在此基础上，项目进一步加入了 Question-aware 压缩方法，使真实 question 能够作为额外信息参与 KV 选择。

五、TabulaKV 方法实现。项目在 Question-aware 压缩的基础上进一步引入表格结构信息。TabulaKV 通过 tokenizer offset mapping 将真实表格中的 header cell 和 body cell 映射到 token-level metadata，并在压缩过程中同步维护这些 metadata，使每轮压缩后的 KV 仍能保留必要的结构标记。方法中还设计了表头 token 保底保留机制，以及 body cell 分数受对应列表头分数影响的加权机制。

六、实验运行与分析。项目在 WikiTableQuestions validation 子集上进行了多轮初步实验，对 Full KV Cache、RKV、Question-aware、Sliding Window、TabulaKV 不同 lambda 设置等进行了比较。由于这些结果主要来自验证集或调试用子集，并非最终测试集结果，报告中不将其作为正式结论性数值呈现。从趋势上看，Full KV Cache 仍然是性能上界；压缩方法在小预算下均会出现不同程度性能下降；TabulaKV 在总体准确率上暂未表现出稳定优势，但在部分依赖列属性或表头语义定位的样本中能够改善保留倾向，说明结构信息仍有进一步挖掘空间。

七、项目整理与开源。将项目代码整理出适合开源的版本，并在 Github 开源平台上开源。同步完成了项目网站作为介绍与宣传。此外，项目代码刻盘提交。

整体来看，项目已经完成了从框架扩展、评测脚本、基线实验、压缩策略实现到项目整理和开源的一条完整研究链路。

研究存在的不足或欠缺，尚需深入研究的问题等。

本项目仍存在一些可以继续完善的地方。

第一，当前 Tabula 方法主要建模列级结构，对行级关系利用不足。WikiTableQuestions 中很多问题需要先根据条件定位某一行，再读取该行中另一列的值。当前方法能够利用表头增强列语义，但对行内 token 的联动保留还不够充分，后续可以引入 row-aware metadata 或 row-level selection。

第二，当前压缩仍然以 token-level top-k 为主，缺少 cell-level 或 tuple-level 的整体约束。表格中的一个单元格通常由多个 token 构成，只保留其中少数 token 可能破坏语义完整性。未来可以尝试先计算 cell 级或 row 级分数，再决定保留哪些 KV。

第三，表头处理策略仍比较初步。当前版本要求每个 header cell 至少保留一个 token，这可以避免长表头直接耗尽 budget，但也可能不足以表达复杂多行表头的完整含义。后续可以探索独立 header budget、question-relevant header selection、长表头关键词抽取等更精细的策略。

总的来说，本项目已经完成了结构化表格场景下 KV Cache 压缩研究的初步探索，搭建了可复现实验框架，并实现了若干 baseline 和一个表格结构感知方法。当前结果表明，表格任务中的 KV Cache 压缩需要显式考虑结构关系，单纯的 token 注意力选择并不足以稳定保留推理所需信息。后续工作将重点围绕行列联合建模、cell-level 压缩、结构化 budget 分配以及更系统的测试集评估展开。
